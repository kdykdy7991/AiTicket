## 一、流程概览

POC 质量问题从发现到批准闭环，共分为 6 个阶段：

1. 发现 POC 问题
2. 确认问题并流转分系统
3. 确认闭环计划
4. POC 问题推进
5. 质量评审／确认
6. 批准人复核（批准闭环）

流程涉及 5 类角色或责任主体：

- 售前
- 专项小组
- 分系统
- 质量
- 批准人（审批提交的问题，并在质量评审后复核批准闭环）

## 二、详细流程

### 01 发现 POC 问题

#### 01-1 发现并提交问题

- **责任方：** 售前（售前与解决方案部）
- **操作入口：** 工单系统
- **主要动作：** 发现质量问题，提交问题，并提出闭环周期要求。
- **提交信息／产出物：** 问题描述及相关要素信息。
- **后续审批：** 提交后由批准人（邱庆举）审批；审批通过后流转至专项小组确认并流转。

### 02 确认问题并流转分系统

#### 02-1 确认问题描述并确定分系统

- **责任方：** 专项小组
- **确认人：** Allen（陈毅君）
- **操作入口：** 工单系统
- **主要动作：** 确认质量问题描述的准确性；同时判定问题涉及的分系统并选定该分系统的负责人。
- **提交方式：** 确认与流转一次完成——提交即流转，不需要再单独执行一次「流转」操作。
- **不通过的处置：** 问题描述不准确、要素不完整或不属于 POC 质量问题范围时，专项小组**驳回**并填写原因，问题退回售前；售前修订后重新提交，由批准人重新审批。
- **涉及系统及人员：**

  1. 系统总体：邓雪群
  2. 卫星平台：卢翔
  3. 终端系统：余华伟
  4. 应用平台：邱庆举
  5. 测运控平台：倪汉华

- **流转结果：** 确认后问题直接进入对应分系统的闭环计划制定环节；**分系统无需再确认接收**（原「03-2 分系统接收问题」环节取消）。

### 03 确认闭环计划

#### 03-1 制定闭环计划

- **责任方：** 对应分系统
- **操作入口：** 工单系统
- **主要动作：** 确定质量问题闭环计划。
- **产出物：** 质量问题闭环计划。

#### 03-2 参与闭环计划确认

- **责任方：** 售前
- **主要动作：** 参与质量问题闭环计划确认。
- **流转结果：** 闭环计划确认后，进入问题分析和验证阶段。

### 04 POC 问题推进

#### 04-1 实施问题分析验证

- **责任方：** 对应分系统
- **操作入口：** 工单系统
- **主要动作：** 按闭环计划实施质量问题分析和验证。
- **产出物：** 质量问题分析报告。
- **过程跟踪：** 质量人员主导质量问题追踪，并维护质量问题跟踪表。

### 05 质量评审／确认

#### 05-1 组织评审与确认

- **责任方：** 质量
- **参与人：** 金凯、马祥艺、巫雪峰
- **操作入口：** 工单系统
- **主要动作：** 基于问题分析和验证结果，组织质量问题评审／确认。
- **输入／过程材料：** 质量问题分析报告、质量问题跟踪表。
- **产出物：** 评审／确认结果。
- **流转结果：** 评审确认后提交批准人复核，批准即闭环。

### 06 批准人复核（批准闭环）

#### 06-1 复核并批准闭环

- **责任方：** 批准人（邱庆举，与售前提交问题的审批为同一人）
- **操作入口：** 工单系统
- **主要动作：** 复核质量评审结果与验证结论，确认后批准闭环。
- **不通过的处置：** 复核不通过时驳回并填写原因，问题退回质量重新评审。
- **流程结果：** 批准后 POC 质量问题完成当前流程闭环。
- **说明：** 缺陷库登记在 SVN 侧按需进行，不作为本流程的流转节点，工单系统内也不填写缺陷 ID 与 SVN 路径。

## 三、端到端流转关系

```text
售前发现并提交问题（工单系统）
  → 批准人（邱庆举）审批
  → 专项小组确认问题描述准确性，并确定涉及的分系统与分系统负责人（一次提交完成确认与流转）
  → 流转到分系统（无需分系统确认接收）
  → 分系统制定质量问题闭环计划（工单系统）
  → 售前参与闭环计划确认
  → 分系统实施问题分析和验证（工单系统）
  → 质量主导问题追踪并维护跟踪表
  → 质量组织问题评审／确认（工单系统）
  → 批准人（邱庆举）复核评审结果并批准闭环（工单系统）
```
