# 星座大系统分支借鉴 POC 流程（已确认口径）

## 适用范围与顺序

仅适用于 `业务保障 → 星座大系统` 及其三级分类。客服仍按现有业务保障表单建单；售后受指派后判断二级分类。选择“星座大系统”时，售后必须补齐下述 12 项，提交分诊后交星座大系统负责人。

```text
客服建单 → 售后选择星座大系统并补齐字段
→ 星座大系统负责人确认并流转（选三级分类及专业责任人）
→ 专业处理人提交响应措施
→ 售后确认响应效果（可退回修改措施）
→ 专业处理人提交分析验证
→ 本项目现有售后致电反馈 → 客服回访/归档
```

保留现有三级分类路由：核心网系统→软件开发组、测运控系统→测运控组、卫星系统→整星产品。POC 的质量评审、售前闭环确认和批准人终审不进入本次流程。

## 售后分诊时补齐的 POC 建单字段

下列字段在售后选择目标分类 `2310`（星座大系统）时显示，并在提交该次分诊时由服务端判定必填；选择其他二级分类不触发。工单已有标题，无需售后补填 POC 的“问题名称”。

| 序号 | 字段 | POC 字段键 |
| --- | --- | --- |
| 1 | 提出人 | `proposer` |
| 2 | 提出部门 | `proposer_department` |
| 3 | 初步排查说明 | `investigation_notes` |
| 4 | 测试场景 | `test_scenario` |
| 5 | 闭环要求 | `closure_requirement` |
| 6 | 测试设备 | `test_device` |
| 7 | 终端固件版本号 | `terminal_firmware_version` |
| 8 | 终端配置 | `terminal_configuration` |
| 9 | 上位机软件 | `host_software` |
| 10 | 选星规则 | `satellite_selection_rule` |
| 11 | 数据频次及数据包长度 | `data_frequency_packet_length` |
| 12 | 部署位置环境状态 | `deployment_environment` |

POC 的 `network_access_number` 对应本项目客服建单的 `satellite_number`（卫星物联网码号），直接复用，售后不重复填写。客户名称、行业、优先级、问题描述、发生时间及地点也使用本项目已有值；优先级仍采用业务保障 P1～P4，不复制 POC 的 P0～P3 编码。经纬度和附件在 POC 建单中选填，可在分诊表单提供选填入口，不阻断提交。

售后分诊发布 `after_sales_triage` v3：上述 12 项仅在目标分类为 `2310` 时显示并必填；选其他二级分类时继续要求 `initial_opinion`（初步核查意见），选星座大系统时不再重复要求它。补充内容进入不可变的节点 Submission，并在详情时间线回显。v1/v2 定义与历史提交保留。

## 四个节点的填写与校验

| 节点 | 责任人 | 提交内容 |
| --- | --- | --- |
| 确认并流转 | 星座大系统负责人 | 确认信息、三级分类、专业处理人。确认信息必填；目标部门由三级分类链确定，处理人须为目标部门在岗成员 |
| 提交响应措施 | 指定专业处理人 | 初步排查结论、临时响应措施必填；长期措施、计划完成时间、附件选填 |
| 确认响应效果 | 售后 | 确认意见可填；退回专业处理人修改措施时，退回原因必填 |
| 提交分析验证 | 指定专业处理人 | 原因分类必填；整改完成时间、过程分析、长期整改措施、验证情况必填。技术原因补机理分析、举一反三及结论；管理原因补责任人与制度完善记录；技术与管理原因两组都填 |

分析验证提交后接回现有售后致电反馈节点，不直接把整单置为 `resolved`。售后提交致电记录后，才进入客服回访和归档。上述新字段及节点只对星座大系统分支生效，其他业务保障分类与其余大类沿用原流程。

## 实施要点

1. 后端将“选择星座大系统并补字段”作为同一笔锁单事务：校验目标分类、表单版本及 12 项后，保存 Submission、变更分类并派给负责人；缺字段不得先改变分类。
2. 负责人确认并流转已发布 `constellation_triage_v2`：选三级分类、填写“确认信息”、指定目标部门的专业处理人，同一事务完成分诊与人员落位；v1 历史记录保留。工单分派链快照扩为响应措施、响应效果确认、分析验证、售后致电反馈四步，并记录对应责任人。
3. 专业处理人的响应措施已发布 `constellation_response_plan_v1`：初步排查结论与临时响应措施必填，长期措施与计划完成时间选填，附件可上传。提交生成独立节点记录，直接交最初选择星座大系统的售后人员确认响应效果。
4. 售后确认效果已发布 `constellation_response_confirmation_v1`：确认意见可选，确认后回到原专业处理人进入分析验证；退回原因必填，退回后回到响应措施节点并带出上次提交内容供修改。
5. 专业处理人的分析验证已发布 `constellation_analysis_v1`：原因分类为技术原因、管理原因、技术与管理原因；共同字段及对应分支字段由后端条件校验。提交后直接交原售后人员致电反馈，致电提交后仍进入本项目已有的客服回访与归档流程。
6. 节点动作与表单条件由后端校验，详情页只展示当前用户允许的动作。退回保留旧提交记录和原因，重新提交生成新记录。
7. 解决 SLA 保留本项目既有规则。POC 的响应措施时限若要复制，应另立计时指标，不能覆盖当前 `solution_deadline`；时长档位须按本项目 P1～P4 确定。
8. 验收覆盖新流转的星座大系统工单：三个三级分类、12 项缺失拦截、其他二级分类不受影响、措施退回重提、分析条件必填，以及分析后进入售后致电反馈。
