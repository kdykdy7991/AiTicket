# 深蓝科技监控风格设计参考

> 依据：参考图1（卫星通信运营概览）、参考图2（人力资源监控大屏），以及后续提供的 Skdy Ticket 工单列表参考图。本文是后续界面改造的视觉设计依据，尚不涉及代码实现。

## 1. 风格定位

整体是**深蓝科技监控风格**：以近黑海军蓝为背景，蓝青色用于边界、强调和数据可视化，白色用于核心信息，少量绿、橙、红区分业务状态。观感应当专业、实时、精密，像运营指挥台，而非普通浅色办公后台。

三张图有不同侧重。最新的工单列表参考图与本项目业务结构最接近，应作为列表页的主要视觉基准：

| 维度 | 参考图1 | 参考图2 | 本项目建议 |
| --- | --- | --- | --- |
| 页面类型 | 带侧栏的日常运营后台 | 全屏数据监控大屏 | 日常业务页以图1为主；统计、总览等展示页可吸收图2 |
| 视觉强度 | 克制的暗色卡片与局部光效 | 强装饰边框、对称布局、霓虹光效 | 根据使用场景分级，避免表单和长列表过度装饰 |
| 信息密度 | 中高，卡片与业务入口并存 | 很高，多模块同时展示 | 工单处理保证可读性；统计页可提高密度 |

## 最新工单列表参考图：明确的落地目标

这张图将前两张图的科技感收敛到实际业务工作台。相较于此前的三方向初稿，它更明确地给出了本项目列表页的目标结构：**顶部窄系统栏、左侧导航、标题与操作按钮、横排状态筛选、组合筛选栏、占据主体的工单表格**。列表页不需要为了呈现科技感而额外插入四张统计指标卡。

后续确定的组合方向是：**以这张工单列表参考图的信息架构为底稿，融入早期“方向 B · 指挥中心”的发光线与仪表感**。发光重点放在顶部框架、选中导航、筛选面板和表格外缘；行内文字、数据与状态仍以清晰阅读为先。

| 区域 | 参考图中的处理 | 对当前项目的映射 |
| --- | --- | --- |
| 顶部与外框 | 近黑蓝底、细电蓝描边、局部切角与微光；顶部保持紧凑 | 用在全局框架，装饰强度集中在边缘，避免覆盖内容 |
| 左侧导航 | 约一列宽的深蓝导航；选中项有亮蓝边框、浅蓝填充与内光 | 保留现有菜单和权限显示规则，调整选中态与分组样式 |
| 页面标题与操作 | 白色大标题；右侧为描边“导出”和亮蓝“新建工单” | 对应当前列表页现有动作，不增添新功能 |
| 状态快捷筛选 | 一排胶囊按钮，选中项亮蓝；状态数量与文本同处一按钮 | 当前列表已有状态切换，但尚未提供每个状态的数量；数量只在数据来源明确后展示 |
| 组合筛选 | 二级分类、优先级、创建人、关键词、日期在同一深蓝描边区域 | 对应当前 `TicketFilters` 的实际字段；保持搜索与日期的可操作空间 |
| 表格 | 蓝色表头、细行线、紧凑行高；状态胶囊、优先级圆点、头像与相对时间形成识别点 | 对应当前列：编号、标签、状态、优先级、处理人、SLA、更新时间；不擅自改变列含义或处理人规则 |
| 色彩重点 | 主操作和选中态用电蓝；状态用蓝、青绿、琥珀等；优先级另用圆点 | 状态、SLA、优先级语义分别制定色表，文字始终保留 |

页面气质是**有边界感的指挥台式工作台**：明显的科技框架与发光细节，内部仍以高效浏览工单为主。图片底部的地球、粒子和轨道纹理属于氛围装饰，可作为侧栏下方的可选素材；它不能进入表格背景，也不能降低导航文字可读性。

实施时需要进一步校准：参考图是约 1670 × 940 的桌面画面；较窄视口应允许表格横向滚动或合理收缩，不能用缩小字体硬塞所有列。参考图中的具体工单数据仅作视觉示意。

## 2. 从参考图提炼的视觉规则

### 色彩

- 背景：近黑蓝或深海军蓝，主体区与侧栏保持可区分的明度层次。
- 面板：比页面背景略亮的深蓝；可用极轻的蓝色渐变增加空间感。
- 主强调色：电光蓝至青蓝，用在激活导航、面板标题装饰、链接、图表和焦点状态。
- 状态色：绿表示正常或完成；黄橙表示关注或预警；红表示严重异常。颜色必须同时配文字，不能单靠色彩传达状态。
- 文字：标题接近白色；正文用浅蓝灰；次要说明再降低亮度，但表格、表单和小字仍需足够对比度。
- 暂定设计令牌方向（待做页面样稿后校准）：页面背景 `#07152B`～`#0B1C35`，面板 `#102541`～`#172D4D`，主文字 `#F2F7FF`，次文字 `#A9BDD5`，强调蓝 `#35A8F5`，描边 `#254A70`。这些是建议值，不是从图片精确取色。

### 构图与层级

- 图1采用“顶部系统栏 + 左侧导航 + 主内容”的管理后台骨架。内容区先放页面标题与关键总览，再放指标卡和主要业务面板。
- 图2采用围绕中心主题的对称大屏结构：中央主视觉或关系图，左右辅助数据，底部横排分布图。适合大屏展示，不宜直接套到工单编辑页。
- 同一层级的指标卡保持尺寸、内边距和数字对齐一致。重要数字大而亮，标签、单位与说明逐级减弱。
- 用深浅背景、细描边和局部高亮组织层次。大块实心亮蓝应少用，以免干扰数据阅读。

### 组件外观

- 面板：深蓝底、细蓝灰边框、轻微内发光或外发光；圆角以小到中等为主。图2的大屏外框可以使用切角和装饰线，但普通业务面板保留简洁轮廓。
- 标题：较粗的白色中文标题，辅以蓝青色短线、斜切块或上边缘高亮；装饰只服务于区分区域。
- 导航：深蓝侧栏，选中项用较亮蓝底或左侧亮线，图标与文字统一变亮。
- 数字卡：缩写或指标名在上，数值为视觉中心，单位和解释在下；状态色点缀，不要让所有卡片同时发光。
- 表格：深色行底、清楚的列边界或行分隔、蓝色悬停态；数值右对齐，状态文本与颜色并用。图2的小字和密集表格只适合远距离展示的辅助区域，不宜照搬到日常操作页。
- 图表：细网格线、蓝青主序列、绿橙红状态序列；图例、坐标轴和提示框要在暗底上清晰可辨。
- 交互控件：输入框、下拉框、按钮、日期选择器和弹窗都应使用同一暗色体系；焦点用可见的蓝青描边，危险操作保留红色语义。

### 字体、间距与动态

- 中文字体以清晰的现代无衬线字体为主；数字可使用字形稳定的等宽或表格数字。中英文混排须保持字重和基线协调。
- 普通业务页标题、表单、列表要优先保证阅读尺寸；不能为了接近大屏截图而缩小文字。
- 面板之间留出明确间距。图2的紧凑布局仅用于固定分辨率大屏，业务页应允许内容滚动与响应式收缩。
- 光效与渐变应局部、低强度使用。实时刷新、悬停、状态变化可有短促反馈；避免持续闪烁和大面积动画。

## 3. 对当前工单系统的应用

当前前端是 Vue + Element Plus，整体使用浅色页面、白色卡片和紫色主色；已有侧栏、顶栏、工单列表、详情、创建、报表、知识库、管理等页面。未来改造应先建立统一的暗色令牌和组件状态，再逐页调整，避免只换背景色造成表格、表单、弹窗仍是浅色。

| 页面/区域 | 建议应用方式 |
| --- | --- |
| 全局框架、侧栏、顶栏 | 参照图1：深蓝结构、明确选中态、简洁的系统身份区域 |
| 工单列表、搜索、管理页 | 图1的简洁面板风格；优先保障筛选、表格、批量操作和分页的阅读效率 |
| 工单详情、创建、草稿 | 使用暗色分区和有限的蓝色强调；表单标签、校验、编辑器与时间线保持清楚的操作层级 |
| 工单统计、线索分析 | 可采用图1的指标卡与趋势面板，并局部引入图2的大屏图表语言 |
| 未来总览/监控大屏 | 可参考图2的中央主视图、左右辅面板与底部指标带，但需以本系统真实指标重组内容 |
| 知识库、智能助手 | 延续统一色板，弱化装饰，保障长文阅读与对话输入体验 |

图中的“卫星”“人力资源”等业务名词、组织树、指标值及装饰框架都属于参考页面内容；本项目应替换为工单、SLA、处理效率、客户反馈等真实业务信息，不直接复制其信息架构。

## 4. 建议的设计优先级与验收标准

1. **基础层**：确认颜色、文字层级、边框、阴影、圆角、图标和状态色，形成可复用令牌。
2. **组件层**：完成导航、卡片、按钮、输入框、表格、标签、弹窗、空状态、加载态、图表提示框的暗色规范。
3. **页面层**：先做全局框架及工单列表样稿，验证日常操作的可读性；再扩展到详情、创建、管理、统计等页面。
4. **大屏层**：如需要独立监控大屏，再建立适合固定展示分辨率的高密度布局与装饰组件。

验收时应检查：页面之间风格一致；常规文本和小字在暗底上可读；键盘焦点清楚；状态不只依赖颜色；表单校验、禁用态、悬停态、弹窗、下拉层与图表均覆盖暗色；常用桌面宽度与较窄视口下无内容遮挡。以上规范需要在真实页面样稿中进一步定稿。
