## 1. Summary

本文档定义 Skdy 工单系统一期（MVP）的产品需求。这是一个面向客服团队的内务工单管理系统，实现工单从创建、分派、处理、回访到归档的完整闭环，通过部门对接人分派机制、SLA 超时自动标记、统计报表等功能提升客服组工作效率和服务质量。

## 3. Background

### 现状与问题

当前客服团队处理用户问题依赖人工分配和线下记录，存在以下痛点：

1. **工单无系统化管理** — 工单的创建、派发、跟进全靠人工，容易遗漏和重复
2. **无法监控处理时效** — 没有超时预警机制，高优先级工单可能被延误
3. **缺少回访闭环** — 工单处理后无法确认用户问题是否真正解决
4. **没有数据支撑** — 无法统计处理效率、超时率、一次解决率等关键指标
5. **通知手段落后** — 催办和提醒依赖口头或微信，容易遗漏

### 为什么现在做

- 业务方已明确提出工单系统需求，并提供了详细的需求清单
- 前端原型已开发完成，验证了核心交互的可行性
- 后端尚未开发，需要尽快推进以实现系统上线

### 一期边界

一期聚焦于**客服坐席内部使用的工单管理**，不包括：
- 客户自助提交工单的门户（客户渠道接入列为二期）
- 呼叫中心集成（来电弹窗、自动外呼）
- 工单自动分流
- 移动端 App

## 4. Objective

### 目标

上线一个可日常使用的工单管理系统，让客服团队从创建工单到回访确认全流程在线化，并通过 SLA 超时预警和统计报表提升服务质量。

### 关键结果（OKR）

| 编号 | 关键结果 | 衡量标准 | 目标值 |
|------|---------|---------|--------|
| KR1 | 工单全流程在线化 | 从创建到结案全程在系统内完成 | 100% 工单在线流转 |
| KR2 | 超时工单零遗漏 | 超时工单自动钉钉通知 | 通知送达率 ≥ 99% |
| KR3 | 回访闭环覆盖 | 已处理工单进入回访流程 | 回访率 ≥ 90% |
| KR4 | 数据可量化 | 日报/周报/月报可自动生成 | 报表数据与实际偏差 ≤ 1% |

### 成功标准

- 系统连续运行 7 天无严重故障
- 客服组全员可正常使用核心流程（建单 → 派发 → 处理 → 回访 → 结案）
- SLA 超时通知在剩余 30 分钟时自动触发钉钉消息
- 统计报表数据可通过导出功能交叉验证

## 7. Solution

### 7.1 用户角色与权限

#### 角色定义

系统使用 `role` 字段区分三类用户，配合「客服组」和「技能组」的归属，实现职责分离：

| 角色（role） | 说明 | 所属组 | 职责 |
|------|------|------|------|
| **管理员** admin | 系统配置、用户管理、全量数据访问 | — | 全权限 |
| **客服团队** agent | 客服组（groups） | 仅客服组 | 创建工单、回访、归档、退回 |
| **部门人员** handler | 技能组（skill_groups） | 仅技能组 | 分派（对接人）/ 处理（处理人） |

> ⚠️ **客服组与技能组互斥**：一个用户要么属于客服组（agent），要么属于技能组（handler），不能同时跨。用户管理界面按角色锁定组类型——选「客服坐席」只能选客服组，选「处理人」只能选技能组。

#### 部门对接人（dispatcher）

技能组内的成员分两种职责，通过 `user_skill_groups.is_dispatcher` 标记：

| 标记 | 职责 | 操作权限 |
|------|------|---------|
| is_dispatcher = true（部门对接人） | 接收待受理工单、分派给具体处理人 | 分派（pending→open）、撤销 |
| is_dispatcher = false（处理人） | 实际处理工单 | 已处理、暂缓、确认 |

> 同一个用户在不同技能组可以是对接人或处理人（按技能组区分）。

#### 客服组长

「客服组长」是 agent 角色的标记（`is_group_leader`），拥有其所属客服组的全局查看权限。

#### 权限矩阵（按状态操作）

| 操作 | 管理员 | 客服团队 | 部门对接人 | 处理人 |
|------|--------|---------|-----------|--------|
| 创建工单（必选对接人） | ✅ | ✅ | ❌ | ❌ |
| 分派 pending→open（选处理人） | ✅ | ❌ | ✅ 本组 | ❌ |
| 标记已处理 open→resolved | ✅ | ❌ | ❌ | ✅ 本人 |
| 暂缓 open→on_hold / 确认 on_hold→resolved | ✅ | ❌ | ❌ | ✅ 本人 |
| 撤销 pending/open→cancelled | ✅ | ✅ 创建者 | ✅ 本组 | ❌ |
| 回访 resolved→callbacked | ✅ | ✅ | ❌ | ❌ |
| 归档 callbacked→archived | ✅ | ✅ | ❌ | ❌ |
| 退回 callbacked→returned | ✅ | ✅ | ❌ | ❌ |
| 批量操作 | ✅ | ✅ | ❌ | ❌ |
| 查看报表 | ✅ | ✅ | ❌ | ❌ |
| 管理后台 | ✅ | ❌ | ❌ | ❌ |

#### 技能组

| 技能组 | 说明 |
|--------|------|
| 技术组 | 技术类问题处理（故障排查、设备问题等） |
| 市场组 | 市场类问题处理（业务咨询、合作洽谈等） |
| 售后组 | 售后类问题处理（报修、投诉等） |

> 技能组可在管理后台增删改，上表为系统初始数据。每个技能组应至少有一个对接人和若干处理人。

### 7.2 工单状态机

#### 状态定义

| 状态 | 编码 | 说明 | 类型 |
|------|------|------|------|
| 待受理 | `pending` | 工单已创建（已指定部门对接人），等待对接人分派处理人 | 初始态 |
| 处理中 | `open` | 对接人已分派处理人，处理人正在处理 | 活跃态 |
| 已处理 | `resolved` | 处理人标记完成，等待客服回访 | 中间态 |
| 暂缓处理 | `on_hold` | 处理人暂缓（可选填暂缓时间），最终回已处理 | 中间态 |
| 已回访 | `callbacked` | 客服已回访确认 | 中间态 |
| 已归档 | `archived` | 客服归档，工单闭环 | **终态** |
| 退回 | `returned` | 已回访工单退回，重新进入处理中 | 回退态 |
| 已撤销 | `cancelled` | 待受理/处理中阶段撤销 | **终态** |

#### 状态流转图

```
┌─────────┐ 分派(对接人)  ┌─────────┐ 处理人完成  ┌─────────┐ 客服回访  ┌─────────┐
│ 待受理   │──────────────►│ 处理中   │────────────►│ 已处理   │─────────►│ 已回访   │
│ pending │              │  open   │            │resolved │          │callbacked│
└────┬────┘              └────┬────┘            └─────────┘          └────┬────┘
     │ 撤销                    │ 暂缓                                      │
     │                  ┌──────▼──────┐ 归档                              ├─归档→ 已归档(终态)
     │                  │ 暂缓处理     │                                  │     archived
     │                  │  on_hold    │                                  │
     │                  └──────┬──────┘ 退回(填原因)                       ├─退回→ 退回 → 处理中
     │                         │ 确认                                   │     returned
     ▼                         └──► 已处理                               ▼
┌──────────┐                                                        (退回后回到处理中)
│  已撤销   │ (终态)
│cancelled │
└──────────┘
```

#### 状态流转规则

| 从 | 到 | 触发条件 | 操作人 |
|----|----|---------|--------|
| 待受理 | 处理中 | 部门对接人分派（必须指定处理人） | 部门对接人、管理员 |
| 待受理 | 已撤销 | 撤销 | 创建者、部门对接人、管理员 |
| 处理中 | 已处理 | 处理人标记完成 | 处理人、管理员 |
| 处理中 | 暂缓处理 | 处理人暂缓（可选填暂缓时间） | 处理人、管理员 |
| 处理中 | 已撤销 | 撤销 | 创建者、部门对接人、管理员 |
| 暂缓处理 | 已处理 | 处理人人工确认 | 处理人、管理员 |
| 已处理 | 已回访 | 客服回访确认 | 客服团队、管理员 |
| 已回访 | 已归档 | 客服归档（闭环） | 客服团队、管理员 |
| 已回访 | 退回 | 客服退回（需填退回原因） | 客服团队、管理员 |
| 退回 | 处理中 | 自动回到处理中，处理人重新处理 | —（自动） |

**业务规则：**

- `已归档` 和 `已撤销` 是终态，不可再流转
- **退回**仅「已回访」状态可触发，其余状态不能退回
- **撤销**仅「待受理」「处理中」可触发，暂缓/已处理/已回访不能撤销
- 退回必须填写退回原因
- 暂缓处理可填暂缓时间（选填，用于 SLA 考核参考），仍需人工确认变回已处理
- 每次状态变更自动记录：操作人、操作时间、原状态、新状态、耗时

### 7.3 SLA 规则

#### 优先级体系

| 等级 | 编码 | 标签颜色 | 首次响应时限 | 解决时限 |
|------|------|---------|------------|---------|
| P1 紧急 | `p1_urgent` | 🔴 红色 | 15 分钟 | 2 小时 |
| P2 严重 | `p2_high` | 🟠 橙色 | 30 分钟 | 4 小时 |
| P3 一般 | `p3_normal` | 🔵 蓝色 | 2 小时 | 8 小时（1 个工作日） |
| P4 政企特急 | `p4_enterprise` | 🟣 紫色 | 10 分钟 | 1 小时 |

> ⚠️ 以上时限为**默认值**，管理员可在后台按技能组 + 优先级组合自定义。系统初始数据使用上表默认值。

#### SLA 计时规则

| 规则 | 说明 |
|------|------|
| 首次响应时间 | 工单从 `待受理` 变为 `处理中` 的耗时（即部门对接人分派处理人的耗时） |
| 解决时间 | 工单从 `待受理` 到 `已处理` 的总耗时 |
| 暂缓不计时 | 工单处于 `暂缓处理` 状态期间暂停 SLA 计时（二期实现，参考 hold_until） |
| 退回重计时 | 工单 `退回` 后自动回到 `处理中`，解决时限从退回时刻重新计算 |
| 工作日计算 | 暂按自然时间计算，不考虑工作日/节假日（二期引入工作日历） |

#### 超时预警规则

| 场景 | 触发条件 | 动作 |
|------|---------|------|
| 即将超时 | 剩余时间 ≤ 20% 且 > 0 | 前端列表该工单行标黄 |
| 超时 | 剩余时间 ≤ 0 | 前端列表该工单行标红 + 置顶 |
| 钉钉预警 | 首次响应剩余 30 分钟 / 解决剩余 1 小时 | 钉钉消息通知当前处理人 |
| 钉钉超时 | 首次响应超时 / 解决超时 | 钉钉消息通知当前处理人 + 组长 |

> 钉钉通知频率：同一工单同一 SLA 类型，预警通知只发 1 次，超时通知只发 1 次。避免重复轰炸。

| 催办 | 催促处理，需填写催办内容 | 所有人可见，且触发钉钉通知 |

#### F4：工单催办

| 字段 | 类型 | 说明 |
|------|------|------|
| 催办时间 | 自动填充 | 当前时间 |
| 发起人 | 自动填充 | 当前用户 |
| 催办内容 | 文本 | 必填 |

**通知规则：** 提交催办后，钉钉消息通知当前处理人，内容包含：工单编号、催办人、催办内容。

#### F5：工单撤销

| 规则 | 说明 |
|------|------|
| 谁能撤销 | 工单创建者、组长、管理员 |
| 可撤销的状态 | 待受理、处理中、挂起 |
| 不可撤销 | 已处理、待回访、已回访、退回（这些已进入确认流程） |
| 撤销后 | 工单变为 `已撤销`，不可恢复 |

#### F6：工单报表

**报表类型：**

**报表视图：** 固定显示「本月」（本月1号~今天），不再区分日报/周报/月报/季度报周期切换。配合每日新增/闭环趋势折线图看趋势。

**报表指标：**

| 指标 | 计算方式 |
|------|---------|
| 新增量 | 时间范围内创建的工单数 |
| 处理中量 | 当前状态=处理中的工单数 |
| 闭环量 | 时间范围内已归档（closed_at）的工单数 |
| 各组平均处理时长 | 各技能组已闭环工单的平均 closed_duration_minutes |
| 超时率 | SLA 超时工单数 / 总工单数 × 100% |
| 一次解决率 | 未被退回过的工单数 / 总工单数 × 100%（查 state_logs 是否有 to_state=returned） |
| 故障分类分布 | 按一级分类统计工单数 |

**报表展示：** 5 个指标卡 + 每日新增/闭环趋势折线图 + 各组处理时长柱状 + 故障分类柱状 + 工单状态饼图 + 优先级饼图。

#### F7：工单查询与导出

**筛选条件：**

| 筛选项 | 类型 | 说明 |
|--------|------|------|
| 工单状态 | 多选 | 全部状态 |
| 优先级 | 多选 | P1-P4 |
| 技能组 | 多选 | — |
| 负责人 | 单选 | — |
| 发起时间范围 | 日期范围 | 起止日期 |
| 办结时间范围 | 日期范围 | 起止日期 |
| 是否超时 | 单选 | 全部 / 是 / 否 |
| 关键词 | 文本 | 模糊匹配标题和描述 |

**导出字段：** 按 V1.1 附件 1 规范，4 大类 22 个字段，用户可勾选导出哪些类。

### 7.5 通知规则汇总

| 事件 | 通知渠道 | 通知对象 | 内容 |
|------|---------|---------|------|
| 工单指派 | 钉钉 | 被指派人 | 工单编号、标题、优先级、SLA 时限 |
| SLA 即将超时（首次响应） | 钉钉 | 当前处理人 | 工单编号、剩余时间 |
| SLA 即将超时（解决） | 钉钉 | 当前处理人 | 工单编号、剩余时间 |
| SLA 已超时（首次响应） | 钉钉 | 当前处理人 + 组长 | 工单编号、已超时时长 |
| SLA 已超时（解决） | 钉钉 | 当前处理人 + 组长 | 工单编号、已超时时长 |
| 工单催办 | 钉钉 | 当前处理人 | 工单编号、催办人、催办内容 |
| 工单退回 | 钉钉 | 被退回的处理人 | 工单编号、退回原因 |
| 工单状态变更 | — | — | 不发通知，在工单详情的流转记录中查看 |

**钉钉集成方式：** 使用钉钉群机器人 Webhook，每个技能组配置一个 Webhook 地址，通知发到对应群。单点通知（如指派给个人）使用钉钉工作通知 API。

### 7.6 数据模型概要

> 以下为核心实体定义，详细表结构在技术设计阶段产出。

#### 核心实体

| 实体 | 说明 | 关键字段 |
|------|------|---------|
| User | 用户 | id, username, name, phone, role(admin/agent/handler), group_id(客服组，agent 才有), is_group_leader, dingtalk_id |
| Group | 客服组 | id, name, dingtalk_webhook_url |
| SkillGroup | 技能组（部门） | id, name, dingtalk_webhook_url |
| UserSkillGroup | 用户-技能组关联 | user_id, skill_group_id, is_dispatcher（是否部门对接人） |
| Ticket | 工单 | id, number, title, state, priority, customer_type, customer_name, customer_phone, device_sn, region_id, channel, category_id, group_id, skill_group_id, **dispatcher_id**(部门对接人), **owner_id**(处理人), creator_id, hold_until(暂缓到时间), is_duplicate, is_escalated, sla_*_breached, first_response_deadline, solution_deadline, ... |
| Article | 工单沟通记录 | id, ticket_id, type(reply/internal_note/addition/reminder), sender_id, body, append_reason, ... |
| TicketStateLog | 状态流转记录 | id, ticket_id, from_state, to_state, operator_id, reason, duration_minutes, created_at |
| TicketCategory | 工单分类（树） | id, parent_id, name, level |
| Region | 区域（树） | id, parent_id, name, level |
| SLAPolicy | SLA 策略 | id, skill_group_id, priority, first_response_minutes, solution_minutes |
| Reminder | 催办记录 | id, ticket_id, sender_id, content, created_at |

> **角色与组互斥**：agent 必须有 group_id（客服组）且无技能组关联；handler 必须有技能组关联且 group_id 为空。
